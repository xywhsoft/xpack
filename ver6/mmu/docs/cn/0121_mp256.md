## MP256（Memory Pool 256）模块：

分类：内存管理器（主要用于管理内存的模块）

MP256 是全功能内存池，他可以做到在稳定的时间周期内，非常高效的分配和释放任意大小的内存。

MP256 通过 BSMM 管理很多个 MMU256 单元，通过二叉树管理一组内存大小节点，并将这些 MMU256 单元归类到对应节点的四个链表内（空闲单元、满载单元、全空单元、已释放单元），每次申请内存时，都会从空闲单元中直接分配，如果没有空闲单元，则会从全空单元或已释放单元中尝试复用，或创建全新的内存管理单元；这个流程中只有线性的代码被执行，所以 MP256 的效率非常高。

MP256 会自动管理内存，当已申请的内存管理单元不足以容纳将要申请的内存数量时，MP256 会自动扩容，当已使用的内存被释放时，MP256 会自动释放不再使用的管理器，但 MP256 总会后备一个空闲的管理器单元作为缓冲，避免在某个临界状态下反复内存申请和释放可能会产生性能问题的情况。

MP256 最多能管理 10 亿个内存数据（1,073,741,823个），超出这个数据数量，只需要少量改进就可以进行扩容。

MP256 非常擅长管理众多的小内存，例如为 表格结构、树结构、大量字符串、各种结构值 提供内存管理能力，能够极为可观的提升运行速度，避免内存碎片化。

作为交换，MP256 会产生一定的内存浪费，例如只申请了 1 个元素内存时，MP256 实际上创建了 256 个元素内存作为缓冲，当然在如今的计算机配置下，这样的浪费是值得的，尤其是当它能够大幅提升程序性能时，与其类似的另一个模块 MM64K 则更为极端，用更大的内存浪费，来换取更加激进的性能。

### MP256_Struct [数据结构]
``` c
// 单个长度区间的内存管理器结构
typedef struct FSB256_Item {
	unsigned int MinLength;						// 支持最小的内存长度
	unsigned int MaxLength;						// 支持最大的内存长度
	MMU256_LLNode* LL_Idle;						// 空闲的 MMU 内存管理单元链表 (优先分配内存的单元)
	MMU256_LLNode* LL_Full;						// 满载的 MMU 内存管理单元链表 (不会从这些单元中分配内存)
	MMU256_LLNode* LL_Null;						// 全空的 MMU 内存管理单元 (备用单元，最多只留一个)
	MMU256_LLNode* LL_Free;						// 已释放的 MMU 内存管理单元链表 (申请新单元优先从这里找)
	struct FSB256_Item* left;					// 左子树
	struct FSB256_Item* right;					// 右子树
} FSB256_Item;

// 256步进内存池数据结构
typedef struct {
	FSB256_Item* FSB_Memory;					// fixed-size-blocks 内存（MP256_Create参数为 1 或 2 时自动创建，否则需要手动创建，不为空会调用 mmu_free 释放）
	FSB256_Item* FSB_RootNode;					// fixed-size-blocks 二叉树（固定大小区块内存管理器阵列）
	BSMM_Struct arrMMU;							// MMU 阵列
	BSMM_Struct BigMM;							// 大内存数组
	MP_BigInfoLL* LL_BigFree;					// 大内存已释放的内存块链表
	MMU_OnErrorProc OnError;					// 错误处理回调函数
} MP256_Struct, *MP256_Object;
```
MP256_Struct 是 MP256 对象的基本结构体数据，可以通过 MP256_Create 函数创建一个指向 MP256_Struct 结构体的指针（也就是 MP256_Object）。

MP256 必须使用已经初始化过的 MP256_Struct 数据结构（使用 MP256_Create），否则在进行 API 调用时，可能产生无法预知的严重后果。

### MP256_Object [对象指针]
MP256_Object 是 MP256_Struct 数据结构的指针，通过 MP256_Create 创建的 MP256 对象会返回 MP256_Object 对象指针。

### MP256_Create - 创建内存管理器
声明：MP256_Object MP256_Create(unsigned int iItemLength);
创建 MP256 对象并初始化数据，创建成功时返回一个 MP256_Object 对象指针，创建失败返回 NULL。
参数 iItemLength 用于指定管理器内，结构体单元的数据长度，通常使用 sizeof 获取对应结构体的内存占用长度。
由 MP256_Create 创建的对象，不再使用时应调用 MP256_Destroy 函数将 MP256 对象销毁，否则会产生内存泄漏。

### MP256_Destroy - 销毁内存管理器
声明：void MP256_Destroy(MP256_Object objMM);
销毁由 MP256_Create 函数创建的 MP256 对象。

### MP256_Init - 初始化内存管理器
声明：void MP256_Init(MP256_Object objMM, unsigned int iItemLength);
这个函数和 MP256_Create 功能类似，它在不申请 MP256 对象内存的情况下，对已存在的 MP256_Struct 数据进行初始化，将 MP256_Struct 嵌入到其他数据结构中的情况下，应使用此函数进行数据初始化。
嵌入到其他数据结构的 MP256_Struct 不再使用时应调用 MP256_Unit 函数释放对象中的数据，否则会产生内存泄漏。

### MP256_Unit - 释放内存管理器
声明：void MP256_Unit(MP256_Object objMM);
释放 MP256 对象内的数据，它会将管理器成员数量清零，并释放管理器占用的内存。

### MP256_Alloc - 申请内存
声明：void* MP256_Alloc(MP256_Object objMP, unsigned int iSize);
申请一块长度为 iSize 的内存，返回内存指针，失败返回 NULL。

### MP256_Free - 释放内存
声明：void MP256_Free(MP256_Object objMM, void* ptr);
释放内存（必须是由 MP256_Alloc 函数申请的，否则可能会导致未知的严重后果）。
一块内存不可以反复释放，否则会扰乱内存申请逻辑。

### MP256_GC_Mark - GC标记
声明：void MP256_GC_Mark(void* obj);
为一块内存添加标记，这个标记可以用于GC内存回收。

### MP256_GC - 执行GC回收内存
声明：void MP256_GC(MP256_Object objMM, int bFreeMark);
执行一轮GC回收，bFreeMark 参数指定了是回收被标记的内存(TRUE)，还是回收没有被标记的内存(FALSE)。
GC回收后，会重置内存的 GC 标记状态。
