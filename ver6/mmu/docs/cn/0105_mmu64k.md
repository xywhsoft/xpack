## MMU64K（Memory Management Unit 64K）模块：

分类：内存管理器（主要用于管理内存的模块）

MMU64K 是一切复杂内存管理器的基础，用于管理固定长度的内存数据，且最多只能管理 65536 个这样的数据。

通常情况下是不推荐您使用这个模块的，它和 BSMM 一样，都属于为了上层建筑更稳固而开发出来的基础模块，使用场景极度受限，但如果你想了解 MM64K 或 MP64K 的运作方式，则可以从了解 MMU64K 开始。

MMU64K 主要作为 MM64K 或 MP64K 的数据阵列单元使用，通过管理 MMU64K 阵列，为内存的申请和释放提供缓冲能力，降低真实的内存申请和释放次数，同时将内存申请和释放操作的理论时间复杂度，降低到 O(1)，这一切都离不开 MMU64K 提供的基础能力。

MMU64K 是为了提升 MM64K 和 MP64K 代码可维护性，被单独提取出来的模块，如果将 MMU64K 部分的代码直接写入 MM64K 或 MP64K，理论上可以微弱的提升性能，但降低了代码可读性，因此它被单独提取为一个独立的模块。

这也符合 MMU 库的设计哲学，追求性能但不会极端的去追求某个单一方向的性能，而是追求最大化的性价比。

### MMU64K_Struct [数据结构]
``` c
typedef struct {
	char* Memory;								// 管理器内存指针（和本结构体同时申请，所以不需要释放）
	unsigned char FreeList[65536];				// 已释放成员列表
	unsigned int ItemLength;					// 成员占用内存长度
	unsigned short Count;						// 成员数量
	unsigned char FreeCount;					// 已释放成员数量
	unsigned char FreeOffset;					// 首个已释放成员在列表中的偏移位置
	unsigned int Flag;							// 值的 Flag 前缀（由上级管理器下发，0-255 区间会被 idx 覆盖）
} MMU64K_Struct, *MMU64K_Object;
```
MMU64K_Struct 是 MMU64K 对象的基本结构体数据，可以通过 MMU64K_Create 函数创建一个指向 MMU64K_Struct 结构体的指针（也就是 MMU64K_Object）。

MMU64K 必须使用已经初始化过的 MMU64K_Struct 数据结构（使用 MMU64K_Create），否则在进行 API 调用时，可能产生无法预知的严重后果。

### MMU64K_Object [对象指针]
MMU64K_Object 是 MMU64K_Struct 数据结构的指针，通过 MMU64K_Create 创建的 MMU64K 对象会返回 MMU64K_Object 对象指针。

### MMU64K_Create - 创建内存管理单元
声明：MMU64K_Object MMU64K_Create(unsigned int iItemLength);
创建 MMU64K 对象并初始化数据，创建成功时返回一个 MMU64K_Object 对象指针，创建失败返回 NULL。
参数 iItemLength 用于指定管理器内，结构体单元的数据长度，通常使用 sizeof 获取对应结构体的内存占用长度。
由 MMU64K_Create 创建的对象，不再使用时应调用 MMU64K_Destroy 函数将 MMU64K 对象销毁，否则会产生内存泄漏。

### MMU64K_Destroy - 销毁内存管理单元
声明：void MMU64K_Destroy(MMU64K_Object objUnit);
销毁由 MMU64K_Create 函数创建的 MMU64K 对象。

### MMU64K_Alloc - 申请内存
声明：void* MMU64K_Alloc(MMU64K_Object objUnit);
申请一块内存，内存长度为管理器单元创建时指定的长度，返回内存指针，失败返回 NULL。

### MMU64K_Free - 释放内存
声明：void MMU64K_Free(MMU64K_Object objUnit, void* obj);
释放内存（必须是由 MMU64K_Alloc 函数申请的，否则可能会导致未知的严重后果）。
一块内存不可以反复释放，否则会扰乱内存申请逻辑。

### MMU64K_FreeIdx - 根据序号释放内存
声明：void MMU64K_FreeIdx(MMU64K_Object objUnit, unsigned char idx);
根据管理器内的 idx 释放内存（idx 范围：0-255）。
不可以反复释放，否则会扰乱内存申请逻辑。

### MM_GC_Mark - GC标记
声明：void MM_GC_Mark(void* obj);
为一块内存添加标记，这个标记可以用于GC内存回收。

### MMU64K_GC - 执行GC回收内存
声明：void MMU64K_GC(MMU64K_Object objUnit, int bFreeMark);
执行一轮GC回收，bFreeMark 参数指定了是回收被标记的内存(TRUE)，还是回收没有被标记的内存(FALSE)。
GC回收后，会重置内存的 GC 标记状态。
